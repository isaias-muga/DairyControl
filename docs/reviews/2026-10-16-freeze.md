## Proposed issues for the private repo (not opened)

- **A. Harden the login:** rate limiting on `/api/Auth/login`, log failed logins without the password, hash both sides before the fixed-time compare, remove the stale comment (finding 1).
- **B. Fail fast on bad configuration:** `ValidateOnStart` for `JwtSettings` and `AdminUserSettings` (minimum key length, non-empty password), and log migration and seeding failures at Critical with context (findings 2, 3).
- **C. Architecture tests for the rules that are only prose:** entities returned from Application or Api, controller attributes, entity and value-object shape, `DbSet` only for roots, no swallowing `catch`, middleware order, csproj references of `Application.Tests`, `limits.ts` against the domain constants; make the `ArgumentException` scan catch qualified names and the `[Authorize]` test select controllers by base type (finding 4).
- **D. Close the test gaps:** controller tests for Proveedores, Configuración and Auth, more `GetResumenAsync` cases, a `Program.cs` wiring test (finding 5).
- **E. Decide the demo credential policy:** document the exception in `CLAUDE.md` or inject it at container start (finding 6).
- **F. Remove the duplicated constants and reject extra decimals in the domain** (findings 8, 9).
- **G. Query and data tidy-ups:** one conditional aggregate for the counts, index `INCLUDE` columns, a ticket search outside the date range, drop the unused repository methods, order the proveedor list, a safer next-ticket suggestion (findings 10, 11).
- **H. Hardening to confirm:** security headers in nginx, an advisory check in CI, and the ticket-numbering question for the plant (findings 12, 13).
